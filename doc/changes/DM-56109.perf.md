Derive configuration lookup keys from storage class names without loading the storage class definitions.

``DatasetType._lookupNames`` previously resolved the storage class, and its parent storage class for components, purely to read back names it already held.
Every datastore configuration lookup goes through this path -- file templates, formatters, composites, cache decisions and constraints -- so each of them imported the associated Python type unnecessarily.
As a consequence ``DatasetType._lookupNames`` no longer raises ``KeyError`` when a storage class name is not registered; an unknown name now fails when the storage class is actually resolved.
